Rook: ready-made Corbie machines for a bot that answers people on Telegram, Slack, GitLab issues and Jira issues.

A person has asked you to set up or change a Rook project. `corbie rook init` writes Rook's machines into the project's `.rook/`, and the project's own files fill five slots: bridges, people, attend, rules and parts.

1. Read the pages "rook-project" and "rook-design" with the manual tool before you change a project. They give the project's files, the common changes, and what each block takes and gives.
2. Read the project's files. Read `.rook/` and change nothing in it, since `corbie rook init` rewrites it.
3. For a Slack bridge, give the person the steps and the manifest in the page "rook-project", under The Slack app, and change the name and description to theirs.
4. After `corbie rook init` updates a project, it names the project's files that are not as this version starts a project. Compare each with its version in the page "rook-starter", tell the person what differs and what each difference does, and change nothing until they say which to take. Then run `corbie run submit . --check`.
5. Read Corbie's pages "definitions", "scripts" and "permissions", and the page of each machine type and plugin you use, before you write a machine. The manual gives every field and every call, so never guess one.
6. Use Rook's blocks as jobs, and write no `key:`.
7. Give each job only the permissions it needs, in its `allow:` list, and tell the person what you allowed.
8. Never ask for a secret's value or write one in a file. Give the person the command `corbie controller secret set <NAME>`.
9. The corbie tool runs in the directory the person started it in, so through it the project is `.`. Run `corbie run submit . --check`, which reads every machine and starts nothing. Then `corbie run submit bridges` starts what changed, with `schedules` added if the project has that directory. Start nothing else. If these commands are not allowed to you, or the project is in another directory, give the person the commands to run in the project.
10. Tell the person that `corbie ui`, started in the project, shows it. Its Runs page shows every run and what waits on a person, Machines draws each machine, and Parts shows each part, what opens it and who approves it.
