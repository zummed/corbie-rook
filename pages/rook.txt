Rook: ready-made Corbie machines for a bot that answers people on Telegram, Slack, GitLab issues and Jira issues.

A person has asked you to set up or change a Rook project. `corbie rook init`
writes Rook's machines into the project's `.rook/`, and the project's own
files fill five slots: bridges, people, attend, rules and parts.

Read a page with the manual tool of corbie mcp, or in a shell with `corbie
rook manual <page>` and `corbie manual <page>`. Run a command with the corbie
tool, or in a shell. Either runs in the project, so the project is `.`.

Before you change a project
---------------------------

1. Read `corbie rook manual rook-project` and `corbie rook manual
   rook-design`. They give the project's files, which piece to add for what
   the person wants, and what each block takes and gives.
2. Read the project's files, and the notes in its `AGENTS.md`. Read
   `.rook/`, and change nothing there, since `corbie rook init` rewrites it.
3. Read `corbie manual definitions`, `corbie manual scripts` and `corbie
   manual permissions`, and the page of each machine type and plugin you
   use, before you write a machine. The manual gives every field and every
   call, so never guess one.

A new project
-------------

`corbie rook init` starts a project with no agent and no part, so the bot
answers nobody. Before you write anything, ask the person:

- who the bot is for, and each person's id on each bridge, for `people.yaml`
- what the bot should do first, which gives its first agent and parts
- who says yes to a tool that changes something
- which model each agent uses, and the name of the secret that holds its key;
  an agent may be a machine with no model

Then add the first agent as `corbie rook manual rook-project` says under Add
an agent, and give the person the secrets and values `init` named.

While you write
---------------

- Choose each piece with the table under Common changes in `corbie rook
  manual rook-project`.
- Change only the agents the person named.
- Use Rook's blocks as jobs, and call `.rook/blocks/ask` with `call:`, as
  `corbie rook manual rook-design` says under Asking a person.
- Give each job only the permissions it needs, in its `allow:` list.
- Never ask for a secret's value or write one in a file. Give the person the
  command `corbie controller secret set <NAME> --at /<project>`, where
  `<project>` is the project directory's name.
- For a Slack bridge, give the person the steps and the manifest under The
  Slack app in `corbie rook manual rook-project`, with their name and
  description.
- Add a line under Notes in the project's `AGENTS.md` for what a later reader
  needs that the files do not say, such as what a part is for.

After you change a project
--------------------------

1. Run each script you wrote that needs no secret with `corbie test`.
2. Run `corbie test .`, which reads every machine and starts nothing.
3. Tell the person each piece you added or changed, by Rook's name for it
   (agent, part, tool, schedule), and why that piece. Tell them what each
   job is allowed.
4. Give the person `corbie run submit .`, to run where the bot runs. Run it
   yourself only when the person asks: a second copy of a bridge takes the
   first one's messages.
5. Tell the person that `corbie ui`, started in the project, shows each run,
   draws each machine, and lists each part with its tools that have
   `approve: true`.

After `corbie rook init` updates a project, it names the project's files that
are not as this version starts a project. Compare each with its version in
`corbie rook manual rook-starter`, and tell the person what differs and what
each difference does. Change nothing until they say which to take.

Reference
---------

  corbie rook manual rook-project    making a project, and the common changes
  corbie rook manual rook-design     the runs that answer a message, what each block takes and gives, and who may do what
  corbie rook manual rook-starter    the files this version starts a project with
